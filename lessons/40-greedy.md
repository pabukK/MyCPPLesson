# 第 40 课:贪心

## 这一课你会学到

- 贪心是什么,和动态规划有什么不同
- 贪心什么时候对,什么时候错,以及怎么判断
- 三个经典问题:活动安排、找零、加油站
- 排序 + 贪心这个最常见的组合

## 1. 贪心是什么

**每一步都选当前看起来最好的那个,不回头。**

对比一下:

| | 贪心 | 动态规划 | 回溯 |
| --- | --- | --- | --- |
| 想法 | 只挑眼前最优 | 记下所有子问题的答案 | 试遍所有可能 |
| 会回头吗 | **不会** | 不会 | 会 |
| 速度 | 最快 | 中等 | 最慢 |
| 正确性 | **不一定对** | 对(状态设计正确的话) | 对 |

贪心的风险就在最后一行:**它快,但可能给出错误答案。** 用贪心之前,必须想清楚"为什么这一步的最优选择不会毁掉整体"。

## 2. 贪心失败的例子

**问题:** 找零,金额 30,可用的硬币面值 `{1, 15, 25}`,要求用最少的枚数。

贪心:先拿最大的 25,剩下 5,只能拿 5 个 1。一共 **6 枚**。

正确答案:15 + 15 = **2 枚**。

贪心错了。因为"先拿 25"这一步,把剩下的 5 变成了很难凑的数。局部的最优,毁掉了整体的最优。

**什么时候贪心才靠谱?** 当问题满足两个性质:

- **贪心选择性质**:存在一个最优解,它包含了"当前看起来最优"的那个选择。
- **最优子结构**:做了这个选择之后,剩下的部分仍然是一个同类型的最优问题。

这两个词不用背,实际操作时按第 5 节的方法判断。

顺带说一句:**人民币、美元的硬币面值(1、2、5、10、20、50……)是特意设计的,贪心一定对。** 所以日常生活中"先拿最大面值"从来不会错。上面的 `{1, 15, 25}` 是我构造的反例。

## 3. 贪心成功的例子:活动安排

**问题:** 有多个活动,各有开始时间和结束时间。一个场地一次只能办一个活动,问最多能办几个。

```text
活动   开始  结束
 A       1     4
 B       3     5
 C       0     6
 D       5     7
 E       3     9
 F       5     9
 G       6     8
 H       8     10
```

直觉上合理的贪心策略有好几个:

- 选**开始最早**的?不一定对。选 C(0 到 6),A(1 到 4)、B(3 到 5)、D(5 到 7) 就都排不进去了。换成 A(0 到 3)、B(1 到 2)、C(2 到 4) 这 3 个,按开始最早会先选 A,只剩 1 个,而正确答案是 2 个。
- 选**持续时间最短**的?也不一定对。在这 8 个活动上它碰巧也排出了 3 个,但那只是巧合:换成 A(0 到 2)、B(0 到 3)、C(0 到 4)、D(2 到 3),它会先选最短的 D(2 到 3),只剩 1 个,而正确答案是 2 个。
- 选**结束最早**的?对。结束得越早,留给后面的时间越多。

正确策略:**按结束时间排序,每次选"开始时间不早于上一个所选活动结束时间"的第一个。**

```text
按结束时间排序后:
 A(1,4)  B(3,5)  C(0,6)  D(5,7)  G(6,8)  E(3,9)  F(5,9)  H(8,10)

last_end 初始为负无穷
A 开始 1 >= 负无穷,选 A,last_end = 4
B 开始 3 < 4,跳过
C 开始 0 < 4,跳过
D 开始 5 >= 4,选 D,last_end = 7
G 开始 6 < 7,跳过
E 开始 3 < 7,跳过
F 开始 5 < 7,跳过
H 开始 8 >= 7,选 H,last_end = 10
结果:A, D, H,共 3 个
```

3 个是不是最优?这个不能靠手推,也不能靠猜。我写了暴力枚举(试遍所有子集,`2⁸ = 256` 种),答案也是 **3**,和贪心一致。再用随机生成的 3000 组数据(每组最多 14 个活动)对比两个算法,**全部一致**。

```cpp
// file: activity_selection.cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<std::pair<int, int>> acts = {{1, 4}, {3, 5}, {0, 6}, {5, 7}, {3, 9}, {5, 9}, {6, 8}, {8, 10}};
    std::sort(acts.begin(), acts.end(), [](const auto& a, const auto& b) {
        return a.second < b.second;
    });

    int count = 0;
    long long last_end = -1000000000LL;
    std::vector<std::pair<int, int>> chosen;
    for (const auto& a : acts) {
        if (a.first >= last_end) {
            chosen.push_back(a);
            last_end = a.second;
            count++;
        }
    }

    std::cout << "最多:" << count << std::endl;
    for (const auto& a : chosen) {
        std::cout << "[" << a.first << "," << a.second << "] ";
    }
    std::cout << std::endl;
    return 0;
}
```

运行结果:

```text
最多:3
[1,4] [5,7] [8,10] 
```

**为什么"结束最早"是对的?** 一句话:选结束最早的活动,不会比其他选择更差。假设某个最优解第一个选的是活动 X,而结束最早的活动是 A。因为 A 结束得比 X 早(或一样早),把 X 换成 A 之后,后面的活动照样都放得下,解的大小不变。所以"存在一个包含 A 的最优解",这就满足了第 2 节说的贪心选择性质。

反过来,前面那两个直觉策略为什么不保险,值得记住:

- **开始最早**:活动 C(0 到 6)占了 6 个单位的时间,把 A、B、D 都挤掉了(G 从 6 开始,还能接上)。在这 8 个活动上它碰巧也排出了 3 个,但换个数据就可能更差。
- **持续最短**:也不保险。前面那个 A(0 到 2)、B(0 到 3)、C(0 到 4)、D(2 到 3) 就是反例。

**这道题的收获,不只是算法,还有方法:贪心的正确性不能靠"感觉有道理",要靠两件事 —— 一个证明思路,加上和暴力法的对拍(第 23 课)。**

## 4. 另一个贪心:分糖果

**问题:** n 个孩子站成一排,每个孩子有一个评分数组 `ratings`。要给他们发糖果:

1. 每人至少一颗。
2. 评分比相邻孩子高的,糖果必须比那个邻居多。

求最少发多少颗。

```text
评分: [1, 0, 2]
中间的孩子评分 0,比两边都低 -> 1 颗
左边的孩子 1 > 0,要比中间多 -> 2 颗
右边的孩子 2 > 0,要比中间多 -> 2 颗
共 5 颗

评分: [1, 2, 2]
第一个 1 颗;第二个 2 > 1,要比左边多 -> 2 颗;第三个 2 不比左边(2)高 -> 1 颗
共 4 颗
```

单方向的贪心不够:一个孩子要同时和**左边**、**右边**比较,而"比左边多"和"比右边多"可能冲突。标准解法是**扫两遍**:

- 从左往右扫:处理"比左边评分高就多给一颗"。
- 从右往左扫:处理"比右边评分高就多给一颗",取两遍结果的**较大值**。

```cpp
// file: candy.cpp
#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

long long candy(const std::vector<int>& ratings) {
    int n = ratings.size();
    if (n == 0) {
        return 0;
    }
    std::vector<int> left(n, 1);
    for (int i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) {
            left[i] = left[i - 1] + 1;
        }
    }

    std::vector<int> right(n, 1);
    for (int i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            right[i] = right[i + 1] + 1;
        }
    }

    long long total = 0;
    for (int i = 0; i < n; i++) {
        total += std::max(left[i], right[i]);
    }
    return total;
}

int main() {
    std::cout << candy({1, 0, 2}) << std::endl;
    std::cout << candy({1, 2, 2}) << std::endl;
    std::cout << candy({1, 3, 4, 5, 2}) << std::endl;
    std::cout << candy({}) << std::endl;
    std::cout << candy({5}) << std::endl;
    return 0;
}
```

运行结果:

```text
5
4
11
0
1
```

对照手推:`{1,0,2}` 是 5,`{1,2,2}` 是 4,都对上了。`{1,3,4,5,2}` 稍长:左扫得 `1,2,3,4,1`,右扫得 `1,1,1,2,1`,逐位取较大值 `1,2,3,4,1`,合计 11。

- 两个方向的约束**必须分开处理**,合成一遍扫是做不到的。这个"两遍扫"的技巧,和第 30 课的前缀和一样:把双向的依赖拆成两个单向的。
- `total` 用 `long long`:n 很大时,糖果总数可能超过 `int`(第 2 课)。
- 空数组和单个元素,都要单独测(第 23 课)。

## 5. 怎么判断一个题能不能贪心

这是贪心唯一"难"的地方。给你几个可操作的办法:

**① 先想清楚"交换论证"。** 假设存在一个最优解,它的第一步不是贪心选的那个。试着把贪心选的那个**换进去**,看解会不会变差。不会变差,就说明"存在一个包含贪心选择的最优解",贪心成立。第 3 节就是这么论证的。

**② 用小数据和暴力法对拍。** 这是最实用的。写一个暴力枚举(第 39 课)或动态规划,随机生成几百上千组小数据,比较两个算法的结果。不一致就找到了反例。

**③ 主动去找反例,而不是找支持自己的例子。** 我在这节课上就犯过这个错:先写了"开始最早""持续时间最短"这些直觉策略,凭感觉就下了结论。后来手推加暴力枚举才发现,在第 3 节那 8 个活动上,它们碰巧都排出了 3 个,和正确答案一模一样 —— 看起来像是"我的直觉没问题",其实只是数据选得巧。换一组数据(第 3 节给了两个)就全错了。**感觉有道理,不等于对。**

**④ 常见的可以贪心的题型:**

| 题型 | 贪心策略 |
| --- | --- |
| 活动安排、会议室 | 按**结束时间**排序 |
| 区间个数最少覆盖 | 按结束时间排序 |
| 加油站(环形路线,看从哪出发能跑完) | 一旦某处累计油量转负,前面的起点都不可能是答案 |
| 分糖果、排队调整 | 两遍扫,取较大值 |
| 找零(面值是常规设计) | 从大到小 |
| 任务调度:最少需要几台机器 | 按开始时间排序 + 小顶堆(第 34 课) |
| 使数组和最大(能选或不选) | 选所有正的 |

**⑤ 常见的贪心陷阱:**

- 找零用奇怪的面值(第 2 节的 `{1, 15, 25}`)。
- "看起来最近的一步"把后面堵死:图的遍历、路径规划。
- 有多个约束互相牵制时,单方向贪心往往不够(第 4 节的分糖果)。
- 0-1 背包**不能**贪心(按性价比排序会错,可以用 DP,第 38 课)。

## 6. 贪心 vs 动态规划,怎么选

| | 贪心 | 动态规划 |
| --- | --- | --- |
| 速度 | `O(n log n)`(排序是大头) | `O(n × 状态数)` |
| 内存 | `O(1)` 或 `O(n)` | 通常 `O(n)` 或 `O(n²)` |
| 正确性 | 需要论证 | 状态设计对了就对 |
| 什么时候用 | 能证明贪心选择性质 | 不能证明,或有多个约束牵制 |

**实操建议:先写 DP。** DP 慢一点,但一定对。跑通了,再想"这里能不能贪心",用对拍验证能换,再换。反过来做(先贪心,错了再回头写 DP)通常更费时间。

## 练习

1. 用暴力枚举验证:0-1 背包(第 38 课的例子)按"性价比最高优先"贪心,能得到正确答案吗?构造一个反例。
2. 合并区间:给一堆区间,把重叠的合并成一个。按什么排序?写出来并用暴力验证。
3. 用贪心解"用最少的箭射爆所有气球"(区间 + 按右端排序),和第 3 节的活动安排比较,它们是同一个模型。
4. 加油站:环形路线,每个站有油量和到下一站的消耗,求出发站。用"累计转负就跳过前面所有起点"的贪心。
5. 把第 2 节的找零例子 `{1, 15, 25}` 改成 DP 求最少枚数(第 38 课的完全背包),和对拍验证贪心在这里是错的。
6. 判断:给一个数组,能不能通过"每次把某个数加 1"使它变成非递减?想想贪心怎么做。

## 小结

- 贪心:每一步只选当前最优,不回头。快,但**可能错**。
- 正确性要靠两件事:**交换论证**(把贪心选择换进最优解,不会变差)+ **和暴力法对拍**。
- 不要凭"感觉有道理"就下结论。主动找反例,比找支持自己的例子更有用。
- 常见策略:按结束时间排序(区间类)、两遍扫取较大值(双向约束)、累计转负就重置起点。
- 0-1 背包、奇怪面值的找零,贪心会错。
- 实操:先写 DP 保证对,再考虑能不能换成贪心。
