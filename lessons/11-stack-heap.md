# 第 11 课:栈与堆,new 和 delete

> 这是内存部分最关键的一课。请放慢速度读。

## 这一课你会学到

- 内存分成两个主要区域:栈和堆
- 为什么需要堆
- 用 `new` 申请内存,用 `delete` 归还内存
- 忘记归还会发生什么

## 1. 两个区域:栈和堆

前面几课创建的变量,都放在一个叫**栈**的区域。

栈的特点是**全自动**:

- 进入大括号,变量创建。
- 离开大括号,变量自动销毁,内存自动归还。

你不用操心。这就是第 6 课说的"出了大括号变量就消失"。

但栈有两个限制:

1. 变量的寿命和大括号绑定,出了大括号就没了。
2. 栈的空间比较小,放不下特别大的数据。

所以还有另一个区域,叫**堆**。

堆的特点是**手动**:

- 你主动申请一块内存,系统给你。
- 这块内存会一直保留,直到你主动归还。
- 空间很大。

打个比方:栈像酒店住宿,退房时(出大括号)自动清房。堆像租仓库,你租了就一直是你的,不退租就一直占着,也一直收费。

## 2. 用 new 申请,用 delete 归还

`new` 的意思是"向堆申请一块内存"。它会返回这块内存的地址,所以要用指针接住。

```cpp
// file: new_delete.cpp
#include <iostream>

int main() {
    int* p = new int;
    *p = 42;
    std::cout << "堆上的值:" << *p << std::endl;

    delete p;
    p = nullptr;
    return 0;
}
```

运行结果:

```text
堆上的值:42
```

逐行看:

- `new int` 向堆申请一个 `int` 大小(4 字节)的内存,返回它的地址。
- `int* p = ...` 用指针 `p` 记住这个地址。(第 9 课:指针就是装地址的变量。)
- `*p = 42;` 顺着地址把值写进去。
- `delete p;` 把这块内存还给系统。
- `p = nullptr;` 还完以后,`p` 里还留着旧地址,但那里已经不属于你了。把 `p` 设成空指针,以后就不会误用。

**铁律:每一个 `new`,都必须有一个对应的 `delete`。** 就像租了仓库必须退租。

## 3. 堆的好处:数据活得比大括号久

栈上的变量出了大括号就没了。堆上的内存不会,所以函数可以把它"交出去"。

```cpp
// file: heap_return.cpp
#include <iostream>

int* make_number() {
    int* p = new int;
    *p = 100;
    return p;
}

int main() {
    int* q = make_number();
    std::cout << "函数结束了,数据还在:" << *q << std::endl;
    delete q;
    q = nullptr;
    return 0;
}
```

运行结果:

```text
函数结束了,数据还在:100
```

`make_number` 里的 `p` 是栈上的指针,函数结束就消失了。但它指向的那块堆内存还在,地址通过 `return` 交给了 `main` 里的 `q`。

注意现在的责任:`make_number` 申请内存,却是 `main` 负责归还。**谁拿着地址,谁就要记得 `delete`。** 这是 C++ 内存管理里最容易出错的地方,下一节会看到出错的样子。

## 4. 在堆上放一排:new[] 和 delete[]

要在堆上放一整排数据,用 `new 类型[个数]`。归还时要用 `delete[]`,**不是** `delete`。

```cpp
// file: new_array.cpp
#include <iostream>

int main() {
    int count = 5;
    int* nums = new int[count];

    for (int i = 0; i < count; i++) {
        nums[i] = i * 10;
    }
    for (int i = 0; i < count; i++) {
        std::cout << nums[i] << " ";
    }
    std::cout << std::endl;

    delete[] nums;
    nums = nullptr;
    return 0;
}
```

运行结果:

```text
0 10 20 30 40 
```

`count` 是运行时才确定的数字,所以能在堆上按需要分配大小。(普通数组的大小必须在写代码时就定死。)

配对规则,请背下来:

| 申请 | 归还 |
| --- | --- |
| `new int` | `delete p` |
| `new int[n]` | `delete[] p` |

配错了,程序行为不可预料。

## 5. 忘记归还:内存泄漏

如果 `new` 了却没有 `delete`,这块内存就永远没人归还。程序里已经没有任何指针记着它的地址,所以也找不回来了。这叫**内存泄漏**。

```cpp
// file: leak.cpp
#include <iostream>

int main() {
    int* p = new int;
    *p = 1;
    std::cout << "我申请了内存,但是没有归还" << std::endl;
    return 0;
}
```

这个程序运行起来没有任何异常现象。泄漏的特点就是**悄无声息**。程序结束时,操作系统会把它用过的内存全部收回,所以这个小程序没有危害。

但如果是一个长期运行的程序(比如服务器、游戏),每次操作都漏一点,慢慢地内存就被吃光,程序越来越慢,最终崩溃。

下一课你会学到一个工具,专门用来发现泄漏。

## 6. 栈和堆对比

| | 栈 | 堆 |
| --- | --- | --- |
| 怎么创建 | `int a = 1;` | `int* p = new int;` |
| 怎么归还 | 出大括号自动归还 | 必须自己 `delete` |
| 空间大小 | 较小 | 很大 |
| 数据活多久 | 到大括号结束 | 到你 `delete` 为止 |
| 出错风险 | 低 | 高(泄漏、重复归还、悬空) |

## 7. 为什么说这很难

不是因为 `new` 和 `delete` 本身难,而是因为**责任不明确时极易出错**:

- 忘了 `delete`:泄漏。
- `delete` 了两次:程序崩溃。
- `delete` 以后还继续用:数据已经不属于你了,读写出错。
- 函数提前 `return`,跳过了后面的 `delete`:泄漏。

下一课会让你亲眼看到这些错误。第 13 课会学到现代 C++ 的做法:**让编译器替你做归还**,基本上不用再手写 `delete`。所以你现在是在理解"问题是什么",之后才会学"怎么避免"。

## 练习

1. 用 `new` 申请一个 `double`,赋值 3.14,输出,然后归还。
2. 让用户输入个数 `n`,用 `new int[n]` 申请数组,读入 n 个数,输出它们的和,最后归还。
3. 写函数 `int* create_array(int n)`,返回堆上的数组,元素为 1 到 n。在 `main` 中使用并归还。

## 小结

- 栈:自动管理,出大括号就归还,空间小。
- 堆:手动管理,`new` 申请,`delete` 归还,空间大,数据能活得更久。
- `new` 和 `delete` 配对,`new[]` 和 `delete[]` 配对。
- 申请了不归还:内存泄漏。
- 归还后把指针设为 `nullptr`。
