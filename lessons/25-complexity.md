# 第 25 课:复杂度,怎么衡量算法的快慢

> 从这一课开始是第六部分:算法与数据结构。
> **算法**就是"解决一个问题的步骤"。同一个问题,不同的步骤,快慢可以差上百万倍。

## 这一课你会学到

- 为什么数据一多,算法的差别就会变得巨大
- 用"数步数"代替"计时"来比较算法
- 常见的几种增长速度:`O(1)`、`O(log n)`、`O(n)`、`O(n²)`
- 怎么估算自己写的代码大概有多快

## 1. 为什么要关心快慢

假设你要在一本通讯录里找一个人:

- **做法 A**:从第一页开始,一页一页翻,直到找到。
- **做法 B**:通讯录按名字排好了,先翻到中间,看名字比要找的大还是小,然后扔掉一半,再在剩下的一半里重复。

通讯录有 100 页时,A 最多翻 100 页,B 大约翻 7 页,差别不大。
通讯录有 1 亿页时,A 最多翻 1 亿页,B 大约翻 27 页。

数据少的时候,算法好坏看不出来。**数据多了,差别就是"能用"和"根本跑不完"。** 所以学算法,首先要学会比较它们。

## 2. 为什么不用计时

最直接的办法是用秒表:程序跑了几秒。但计时有三个问题:

1. 换一台电脑,时间就不同。
2. 电脑同时在做别的事,时间也会晃动。
3. 小数据测出来没有差别,看不出规律。

所以我们换一种办法:**数程序执行了多少"基本步骤"**,比如比较了多少次、加了多少次。再看**数据量 n 变大时,步数怎么变**。这个变化规律,叫**时间复杂度**。

## 3. 数一数步数

```cpp
// file: count_steps.cpp
#include <iostream>

int main() {
    std::cout << "n     一层循环  两层循环  每次减半" << std::endl;
    for (int n : {10, 100, 1000}) {
        long long one_loop = 0;
        for (int i = 0; i < n; i++) {
            one_loop++;
        }

        long long two_loops = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                two_loops++;
            }
        }

        long long halving = 0;
        for (int k = n; k > 1; k /= 2) {
            halving++;
        }

        std::cout << n << "     " << one_loop << "       " << two_loops << "     " << halving << std::endl;
    }
    return 0;
}
```

运行结果:

```text
n     一层循环  两层循环  每次减半
10     10       100     3
100     100       10000     6
1000     1000       1000000     9
```

(`long long` 是第 2 课提过的、比 `int` 范围更大的整数。)

观察,n 每扩大 10 倍:

- 一层循环:步数也扩大 10 倍。
- 两层循环:步数扩大 100 倍。
- 每次减半:步数只增加了 3 左右。

## 4. 大 O 记法

数学家用 `O(...)` 来概括这种增长规律,读作"大 O"。括号里写 n 的式子,表示"步数大约和它成正比"。**只看增长最快的那一项,省略系数和小项。**

| 记法 | 读法 | 通俗说法 | 例子 |
| --- | --- | --- | --- |
| `O(1)` | 常数 | 不管数据多少,步数不变 | 按下标取 `v[5]` |
| `O(log n)` | 对数 | 数据翻倍,只多一步 | 二分查找(第 29 课) |
| `O(n)` | 线性 | 数据翻倍,步数翻倍 | 遍历一遍,求和 |
| `O(n log n)` | | 比线性略慢一点 | 好的排序(第 28 课) |
| `O(n²)` | 平方 | 数据翻 10 倍,步数翻 100 倍 | 两层循环,简单排序(第 27 课) |
| `O(2ⁿ)` | 指数 | 数据多一个,步数翻倍 | 暴力枚举所有子集(第 39 课) |

这里的 `log n` 指"n 不断除以 2,要除几次才变成 1"。上面"每次减半"的循环,步数就是它。

举个省略规则的例子:一段代码一共执行 `3n² + 5n + 100` 步,我们就说它是 `O(n²)`。因为 n 很大时,`n²` 这一项远远盖过其他项,系数 3 也不影响"增长的形状"。

## 5. 数据量大了以后差多少

假设电脑每秒执行 1 亿(10⁸)步:

| n | `O(n)` | `O(n log n)` | `O(n²)` | `O(2ⁿ)` |
| --- | --- | --- | --- | --- |
| 1000 | 瞬间 | 瞬间 | 0.01 秒 | 宇宙寿命都不够 |
| 10 万 | 瞬间 | 0.02 秒 | 约 100 秒 | |
| 100 万 | 0.01 秒 | 0.2 秒 | 约 3 小时 | |
| 1 亿 | 1 秒 | 约 27 秒 | 约 3 年 | |

**一个实用的经验:** 一秒钟内,`O(n²)` 大约能处理一万到十万个数据,`O(n log n)` 能处理几百万,`O(n)` 能处理一亿左右。拿到一个问题,先看数据量有多大,就知道什么级别的算法才够用。

## 6. 怎么估算自己代码的复杂度

看循环,按下面几条估:

| 代码的样子 | 复杂度 |
| --- | --- |
| 几行普通语句,没有循环 | `O(1)` |
| 一层循环,从 0 到 n | `O(n)` |
| 两层循环,各自从 0 到 n | `O(n²)` |
| 两个循环一个接着一个(不嵌套) | `O(n) + O(n)`,还是 `O(n)` |
| 循环变量每次乘 2 或除 2 | `O(log n)` |
| 循环里调用了一个 `O(n)` 的函数 | `O(n) × O(n)` = `O(n²)` |

**嵌套是相乘,先后是相加。** 相加时只保留大的那个。

要小心"藏起来的循环":下面这段看起来只有一层循环,其实是两层。

```cpp
// file: hidden_loop.cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {5, 3, 8, 1, 9, 2};
    int hits = 0;
    for (int i = 0; i < 6; i++) {
        if (std::find(v.begin(), v.end(), i) != v.end()) {
            hits++;
        }
    }
    std::cout << "出现过的数:" << hits << " 个" << std::endl;
    return 0;
}
```

运行结果:

```text
出现过的数:4 个
```

问的是"0 到 5 这几个数里,有几个在 `v` 里"。`v` 里是 1、2、3、5,所以是 4 个 —— 0 和 4 并不在里面。

外面的 `for` 是 `O(n)`,里面的 `std::find` 要从头到尾找,也是 `O(n)`。合起来是 `O(n²)`。以后用标准库的函数时,要知道它们自己的复杂度,不然会不知不觉写出很慢的代码。(第 43 课会列表。)

## 7. 实测:同一个问题,两种做法

问题:给 n 个数,问其中有没有两个数相等。

- 做法一:每个数都和后面的每个数比一遍。`O(n²)`。
- 做法二:先排序,相等的数必然挨在一起,只比较相邻的。`O(n log n)`。

用计时验证一下。这里只用来说明"差距真的有这么大",具体数字每台电脑都不同。

```cpp
// file: compare_speed.cpp
#include <algorithm>
#include <chrono>
#include <iostream>
#include <vector>

bool has_duplicate_slow(const std::vector<int>& v) {
    for (std::size_t i = 0; i < v.size(); i++) {
        for (std::size_t j = i + 1; j < v.size(); j++) {
            if (v[i] == v[j]) {
                return true;
            }
        }
    }
    return false;
}

bool has_duplicate_fast(std::vector<int> v) {
    std::sort(v.begin(), v.end());
    for (std::size_t i = 1; i < v.size(); i++) {
        if (v[i] == v[i - 1]) {
            return true;
        }
    }
    return false;
}

int main() {
    for (int n : {1000, 10000, 40000}) {
        std::vector<int> v;
        for (int i = 0; i < n; i++) {
            v.push_back(i);
        }

        auto t0 = std::chrono::steady_clock::now();
        bool a = has_duplicate_slow(v);
        auto t1 = std::chrono::steady_clock::now();
        bool b = has_duplicate_fast(v);
        auto t2 = std::chrono::steady_clock::now();

        auto ms = [](auto from, auto to) {
            return std::chrono::duration_cast<std::chrono::microseconds>(to - from).count() / 1000.0;
        };
        std::cout << "n=" << n << "  慢:" << ms(t0, t1) << " 毫秒  快:" << ms(t1, t2)
                  << " 毫秒  结果相同:" << (a == b) << std::endl;
    }
    return 0;
}
```

我这台机器上的运行结果(没有开优化,你的数字会不同,但规律一样):

```text
n=1000  慢:1.546 毫秒  快:0.063 毫秒  结果相同:1
n=10000  慢:162.679 毫秒  快:0.883 毫秒  结果相同:1
n=40000  慢:2697.03 毫秒  快:4.457 毫秒  结果相同:1
```

看 n 从 10000 涨到 40000(4 倍):

- 慢的做法:从 162 毫秒变成 2697 毫秒,大约涨了 16 倍,正好是 4 的平方。这就是 `O(n²)`。
- 快的做法:从 0.9 毫秒变成 4.5 毫秒,大约涨了 5 倍,略多于 4 倍。这就是 `O(n log n)`。

n = 40000 时,快的做法比慢的快了 600 多倍。再大一些,慢的做法就会慢到不能用。

**这一课的重点:拿到问题,先估算复杂度,再决定写法。**

## 8. 空间复杂度

除了"花多少步",还可以问"多用了多少内存"。这叫**空间复杂度**,同样用大 O 表示。

- 只用了几个变量:`O(1)`。
- 复制了一份长度为 n 的数据:`O(n)`。

上面的 `has_duplicate_fast` 为了不改动原数据,把 `v` 复制了一份再排序,所以用了 `O(n)` 的额外内存。时间和空间常常要**互相换**:多用内存,能换来更快的速度(第 31 课哈希表就是典型);省内存,可能要多花些时间。

## 9. 最好、最坏、平均

同一个算法,输入不同,步数也不同。比如在一排数里找一个数,从头找:

- 最好:第一个就是,1 步。
- 最坏:最后一个才是,或者根本没有,n 步。

通常我们说一个算法的复杂度,指的是**最坏情况**,因为它是一个"保证":再倒霉也不会比这更慢。有些算法最坏情况很少出现,会同时说明"平常"的速度,遇到时我会指出来。

## 小结

- 比较算法不靠计时,而是看"数据量变大时,步数怎么增长"。
- 大 O 记法只看增长最快的一项,省略系数。
- 常见顺序,从快到慢:`O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n²)`、`O(2ⁿ)`。
- 嵌套的循环相乘,先后的循环相加。
- 标准库函数里面也可能藏着循环。
- 时间和空间常常可以互相交换。
- 说复杂度,通常指最坏情况。
