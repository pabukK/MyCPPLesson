# 第 26 课:递归

## 这一课你会学到

- 递归是什么:函数调用它自己
- 写递归的两个关键:终止条件和缩小问题
- 递归在内存里是怎么运行的(和第 11 课的"栈"有关)
- 递归的陷阱:太深会崩溃,重复计算会很慢

## 1. 递归是什么

先看一个生活里的例子。你站在一支长队里,想知道自己排第几,但前面看不到头。你可以问前面的人:"你排第几?"他也不知道,就再问他前面的人……一直问到队首的人,他说"我是第 1"。然后每个人把答案加 1,依次传回来。

这就是**递归**:**要解决一个问题,先去解决一个更小的同类问题,再用小问题的结果得出答案。**

在代码里,递归就是**函数调用它自己**。

## 2. 第一个例子:阶乘

n 的阶乘是 1 × 2 × 3 × … × n,记作 n!。比如 5! = 120。

观察:5! = 5 × 4!,而 4! = 4 × 3!,依此类推。**n! = n × (n-1)!**。这就是"用更小的同类问题,得出答案"。

```cpp
// file: factorial.cpp
#include <iostream>

long long factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

int main() {
    std::cout << "5! = " << factorial(5) << std::endl;
    std::cout << "10! = " << factorial(10) << std::endl;
    return 0;
}
```

运行结果:

```text
5! = 120
10! = 3628800
```

写递归永远要想清楚两件事:

1. **终止条件**:问题小到不用再拆时,直接给出答案。这里是 `n <= 1` 时返回 1。没有它,函数会无限调用下去。
2. **缩小问题**:每次调用,问题必须变小,最终能走到终止条件。这里每次 `n - 1`。

## 3. 递归是怎么执行的

`factorial(3)` 的执行过程:

```text
factorial(3) 想算 3 * factorial(2),要先等 factorial(2) 的结果
  factorial(2) 想算 2 * factorial(1),要先等 factorial(1) 的结果
    factorial(1) 直接返回 1
  factorial(2) 得到 1,返回 2 * 1 = 2
factorial(3) 得到 2,返回 3 * 2 = 6
```

每次调用函数,系统都要在**栈**上(第 11 课:栈是自动管理、空间较小的内存区域)为这一次调用留一块地方,存放它的参数和局部变量。递归时,"等待中"的每一层都占着一块。

这有一个直接的后果:**递归太深,栈就会被用光,程序崩溃。**这叫**栈溢出**。

## 4. 递归太深会崩溃

下面的函数算 1 + 2 + … + n,写成递归。n 小时没问题,n 太大时会怎样?

<!-- expect: crash -->
```cpp
// file: too_deep.cpp
#include <iostream>

long long sum_to(long long n) {
    if (n == 0) {
        return 0;
    }
    return n + sum_to(n - 1);
}

int main() {
    std::cout << sum_to(1000) << std::endl;
    std::cout << sum_to(10000000) << std::endl;
    return 0;
}
```

第一行输出 `500500`,第二行调用要嵌套一千万层,栈装不下,程序崩溃(Linux 下报 `Segmentation fault`,意思是访问了不该访问的内存)。

我在 WSL 里测过:栈大小限制是 8 MB 时,这个函数无优化编译,递归 10 万层还能运行,100 万层就崩溃了。不同电脑、不同编译选项,界限会不同,但**"递归深度大到一定程度,就会崩溃"这一点是一定的**。

注意:开了优化(`-O2`)后,编译器有时能把这种递归自动改写成循环,看起来就不崩溃了。但不要依赖它。

**怎么办:**

- 估算最大深度。深度只有几十、几百层,放心用递归。
- 深度可能到几万以上,就改成循环(见下一节)。

## 5. 递归和循环可以互相改写

求和用循环写,又简单又不会栈溢出:

```cpp
// file: sum_loop.cpp
#include <iostream>

long long sum_to(long long n) {
    long long total = 0;
    for (long long i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

int main() {
    std::cout << sum_to(1000) << std::endl;
    std::cout << sum_to(10000000) << std::endl;
    return 0;
}
```

运行结果:

```text
500500
50000005000000
```

那为什么还要学递归?因为有些问题天然就是"大问题里套着同样结构的小问题",比如树(第 33 课)、图的搜索(第 35 课)、排列组合(第 39 课)、归并排序和快速排序(第 28 课)。用递归写,几行就能表达清楚,用循环写要自己模拟栈,又长又乱。

## 6. 另一个陷阱:重复计算

斐波那契数列:1, 1, 2, 3, 5, 8, 13, …,每一项等于前两项之和。写成递归非常自然:

```cpp
// file: fib_slow.cpp
#include <iostream>

long long calls = 0;

long long fib(int n) {
    calls++;
    if (n <= 2) {
        return 1;
    }
    return fib(n - 1) + fib(n - 2);
}

int main() {
    for (int n : {10, 20, 30}) {
        calls = 0;
        long long result = fib(n);
        std::cout << "fib(" << n << ") = " << result << ",调用了 " << calls << " 次" << std::endl;
    }
    return 0;
}
```

运行结果:

```text
fib(10) = 55,调用了 109 次
fib(20) = 6765,调用了 13529 次
fib(30) = 832040,调用了 1664079 次
```

n 每加 10,调用次数涨了约 120 倍。这是指数级增长(`O(2ⁿ)`,第 25 课)。原因是同样的小问题被反复计算:算 `fib(5)` 要算 `fib(4)` 和 `fib(3)`;算 `fib(4)` 又要算一遍 `fib(3)`……

```text
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2)
│   │   └── fib(1)
│   └── fib(2)
└── fib(3)          <- fib(3) 又被算了一遍
    ├── fib(2)
    └── fib(1)
```

## 7. 解决办法:把算过的结果记下来

给每个已经算出来的结果做个记录,下次再要就直接查,不用重新算。这个办法叫**记忆化**。

```cpp
// file: fib_memo.cpp
#include <iostream>
#include <vector>

long long calls = 0;

long long fib(int n, std::vector<long long>& memo) {
    calls++;
    if (n <= 2) {
        return 1;
    }
    if (memo[n] != 0) {
        return memo[n];
    }
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
    return memo[n];
}

int main() {
    for (int n : {10, 30, 80}) {
        std::vector<long long> memo(n + 1, 0);
        calls = 0;
        long long result = fib(n, memo);
        std::cout << "fib(" << n << ") = " << result << ",调用了 " << calls << " 次" << std::endl;
    }
    return 0;
}
```

运行结果:

```text
fib(10) = 55,调用了 17 次
fib(30) = 832040,调用了 57 次
fib(80) = 23416728348467685,调用了 157 次
```

调用次数从指数级,降到了和 n 成正比(`O(n)`)。`fib(80)` 用慢的做法,要比宇宙年龄还久,用记忆化只要 157 次。

- `memo` 是一个 `vector`,`memo[n]` 记录 `fib(n)` 的结果,0 表示"还没算过"。
- 参数 `std::vector<long long>& memo` 是引用(第 10 课),所有层的调用共用同一个记录。

记忆化是第 38 课"动态规划"的核心思想,那一课会系统地讲。

## 8. 经典例子:快速幂

算 x 的 n 次方。直接乘 n 次是 `O(n)`。用递归,利用"一半一半地算":

- n 是偶数:`x^n = (x^(n/2))²`
- n 是奇数:`x^n = x × x^(n-1)`

```cpp
// file: power.cpp
#include <iostream>

long long power(long long x, int n) {
    if (n == 0) {
        return 1;
    }
    if (n % 2 == 0) {
        long long half = power(x, n / 2);
        return half * half;
    }
    return x * power(x, n - 1);
}

int main() {
    std::cout << "2^10 = " << power(2, 10) << std::endl;
    std::cout << "3^13 = " << power(3, 13) << std::endl;
    std::cout << "2^62 = " << power(2, 62) << std::endl;
    return 0;
}
```

运行结果:

```text
2^10 = 1024
3^13 = 1594323
2^62 = 4611686018427387904
```

每两步,指数至少减半,所以只要 `O(log n)` 步。算 `2^62` 只需要不到 12 次调用。注意 `half` 只算一次并保存起来,如果写成 `power(x, n/2) * power(x, n/2)`,就会重复计算,又退回到 `O(n)`,这正是上一节的陷阱。

(这里用 `long long`,`2^63` 以上就装不下了,会溢出,第 2 课说过。)

## 9. 经典例子:汉诺塔

三根柱子,左边柱子上有 n 个大小不同的盘子,大的在下,小的在上。要全部搬到右边的柱子,规则:

- 一次只能搬一个盘子。
- 大盘子不能压在小盘子上面。

递归的想法:**要搬 n 个盘子,先把上面的 n-1 个搬到中间柱子,再把最大的搬到右边,最后把 n-1 个从中间搬到右边。** 其中"搬 n-1 个"是同样的问题,只是更小。

```cpp
// file: hanoi.cpp
#include <iostream>

void hanoi(int n, char from, char to, char via) {
    if (n == 0) {
        return;
    }
    hanoi(n - 1, from, via, to);
    std::cout << "盘子 " << n << ":" << from << " -> " << to << std::endl;
    hanoi(n - 1, via, to, from);
}

int main() {
    hanoi(3, 'A', 'C', 'B');
    return 0;
}
```

运行结果:

```text
盘子 1:A -> C
盘子 2:A -> B
盘子 1:C -> B
盘子 3:A -> C
盘子 1:B -> A
盘子 2:B -> C
盘子 1:A -> C
```

3 个盘子要搬 7 次。n 个盘子要搬 `2ⁿ - 1` 次,是指数级,这个问题本身就无法更快。

## 10. 写递归的步骤

遇到一个问题,想用递归,按这几步想:

1. **这个问题怎么变小?** 找到"同样的问题,但规模更小"。
2. **最小的情况是什么?** 小到什么程度,可以直接回答,不用再拆。这就是终止条件。
3. **大问题的答案,怎么用小问题的答案拼出来?**
4. **相信小问题会被正确解决。** 不要在脑子里一层层展开,展开会晕。只要保证 1~3 对了,递归自然对。
5. **检查:每次调用,问题都在向终止条件靠近吗?** 否则就是死递归。

## 练习

1. 写递归函数,求 1 + 2 + … + n(用递归,n 取 1000)。
2. 写递归函数,判断一个字符串是不是回文(正着读反着读一样)。提示:比较首尾,再判断中间那部分。
3. 写递归函数 `int digit_sum(int n)`,求各位数字之和,比如 `digit_sum(1234)` 是 10。提示:`n % 10` 是最后一位,`n / 10` 去掉最后一位。
4. 用递归求两个数的最大公约数:`gcd(a, b)`,如果 `b == 0` 返回 `a`,否则返回 `gcd(b, a % b)`。想想为什么这样做是对的。
5. 修改汉诺塔,让它数一共搬了多少次,验证是 `2ⁿ - 1`。

## 小结

- 递归就是函数调用自己,把大问题拆成同类的小问题。
- 必须有**终止条件**,并且每次调用都**让问题变小**。
- 每一层调用都占用栈空间,太深会栈溢出崩溃。
- 同一个小问题被重复计算,会让速度暴跌。用**记忆化**把结果存下来。
- 递归能做的,循环也能做;但树、图、排列组合这类问题,递归写起来清楚得多。
- 写递归的时候,不要展开想,相信小问题已被解决。
